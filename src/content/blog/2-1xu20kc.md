## 一.MD5

**MD5 其实不是“加密”（Encryption），而是“散列 / 哈希”（Hash）。** 加密是可以解密的（比如把 A 变成 B，还能用钥匙把 B 变回 A）；而 MD5 是单向的，把 A 变成一串 32 位的字符后，**理论上是绝对无法逆向解密还原的**。这也是为什么我们用它来存密码，哪怕数据库泄露，黑客也看不到用户的明文密码。

也可以直接使用Hutool的md5加密的工具类，更加的方便

### 1. 基础用法 

在 Spring Boot 中，你不需要引入任何额外的依赖，直接使用 `org.springframework.util.DigestUtils` 即可。

```java
        String password = "123456";
        
        // 核心代码：调用 Spring 自带的 DigestUtils
        // 注意：MD5 计算的是字节数组，所以要用 .getBytes()
        String md5Result = DigestUtils.md5DigestAsHex(password.getBytes());
        
        System.out.println("原始密码: " + password);
        System.out.println("MD5结果: " + md5Result); 
        // 输出: e10adc3949ba59abbe56e057f20f883e
```

### 2. 加盐 (Salt)

如果你直接像上面那样存 MD5，会面临一个致命的安全漏洞：**彩虹表破解（Rainbow Table）**。

因为 MD5 的算法是公开且固定的，`123456` 的 MD5 永远是 `e10adc3949ba59abbe56e057f20f883e`。黑客早就预先计算好了几百亿个常用弱密码的 MD5 值存在一个巨大数据库里（这就是彩虹表）。如果你的数据库泄露，黑客拿着 `e10adc...` 去表里一搜，瞬间就知道密码是 `123456`。

**解决办法就是“加盐”（Salt）：**

我们在用户的密码前面或后面，拼接一段复杂且毫无规律的字符串（比如 Rentify 项目的专属标识），然后再进行 MD5 计算。

```java
public class Md5SaltUtils {
    // 定义一个固定的盐值 (实际项目中可以放在 yml 里)
    private static final String SALT = "Rentify@2026_SuperSecure!";
    /**
     * 生成加盐后的 MD5 密码
     */
    public static String getSaltedMd5(String password) {
        // 将明文密码和盐值拼接在一起
        String saltedPassword = password + SALT;
        
        // 对拼接后的字符串进行 MD5 计算
        return DigestUtils.md5DigestAsHex(saltedPassword.getBytes());
    }
    public static void main(String[] args) {
        String password = "123456";
        
        String normalMd5 = DigestUtils.md5DigestAsHex(password.getBytes());
        String saltedMd5 = getSaltedMd5(password);
        
        System.out.println("普通MD5: " + normalMd5); 
        System.out.println("加盐MD5: " + saltedMd5); 
        // 哪怕用户用的是 123456，加盐后的 MD5 值黑客也绝对查不出！
    }
}
```



## 二.BCryptPasswordEncoder

BCrypt 的核心优势在于它**自带随机加盐（Salt）机制**。这意味着，即使两个用户的明文密码完全一样（比如都是 `123456`），经过 BCrypt 加密后存入数据库的密文也是**完全不同**的。

### 1. 引入依赖

`BCryptPasswordEncoder` 包含在 Spring Security 中

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
```

*(注：如果你的项目不想引入重量级的 Spring Security，你也可以单独引入 `spring-security-crypto` 依赖来仅使用加密功能。)*

### 2. 配置 SecurityConfig

在 Spring Boot 中，推荐的做法是将 `BCryptPasswordEncoder` 注册为一个全局的 Bean，这样你就可以在任何地方通过 `@Autowired` 或构造器注入来使用它。：

```java
@Configuration
public class SecurityConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        // 也可以传入强度参数，例如 new BCryptPasswordEncoder(12)
        // 默认强度是 10，数字越大，加密过程越慢，越能防范暴力破解
        return new BCryptPasswordEncoder(); 
    }
}
```

### 3. 加密密码并存入数据库

当用户注册或修改密码时，你需要对他们输入的明文密码进行加密。

```java
@Service
@RequiredArgsConstructor
public class UserService {
    private final PasswordEncoder passwordEncoder;

    public void registerUser(String username, String rawPassword) {
        // 1. 将明文密码加密
        String encodedPassword = passwordEncoder.encode(rawPassword);
        
        System.out.println("原始密码: " + rawPassword);
        System.out.println("存入数据库的密文: " + encodedPassword); 
        // 输出类似: $2a$10$wY.u9M2.... 每次运行结果都不一样！

        // 2. 将 username 和 encodedPassword 存入数据库
        // userRepository.save(new User(username, encodedPassword));
    }
}
```

### 4. 校验密码

> **⚠️ 最常见的错误预警：**
>
> 很多新手在登录时，会尝试将用户输入的密码再次 `encode()`，然后去和数据库里的密文做字符串对比（`equals`）。**这在 BCrypt 中是绝对行不通的！** 因为每次 `encode` 产生的密文都不一样。

**正确的做法是使用 `matches()` 方法。** BCrypt 会自动从数据库提取的密文中读取出当初使用的“盐”，然后用同样的规则计算明文，看是否匹配。

```java
    public boolean login(String username, String rawPasswordFromUser) {
        // 1. 根据用户名从数据库中查出之前保存的密文密码
        // User user = userRepository.findByUsername(username);
        // String encodedPasswordFromDb = user.getPassword();
        
        // 假设这是我们从数据库查出来的密文
        String encodedPasswordFromDb = "$2a$10$wY.u9M2O... (省略)"; 

        // 2. 使用 matches() 方法进行比对
        // 参数1: 用户刚输入的明文密码
        // 参数2: 数据库里的密文密码
        boolean isMatch = passwordEncoder.matches(rawPasswordFromUser, encodedPasswordFromDb);

        if (isMatch) {
            System.out.println("密码正确，登录成功！");
            return true;
        } else {
            System.out.println("密码错误！");
            return false;
        }
    }
```

**核心总结**:

1. **加密用 `encode(rawPassword)`**：只在注册或修改密码时调用。
2. **校验用 `matches(rawPassword, encodedPassword)`**：只在登录认证时调用，**绝对不要**用字符串 `equals` 去对比两个密码。
3. **密文长度**：BCrypt 加密后的字符串长度固定为 **68 个字符**（有时是 60 个，取决于具体实现版本）。因此，设计数据库表结构时，密码字段 `password` 建议设置为 `VARCHAR(100)` 以防万一，千万不要设置为 `VARCHAR(32)`（那是留给 MD5 的）。
