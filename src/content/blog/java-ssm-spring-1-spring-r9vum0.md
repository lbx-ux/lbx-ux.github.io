## 1. Spring

**Spring** 是一个开源的 Java 基础开发框架，核心目标只有一个：**通过简化开发流程与解耦，让开发者专注写核心业务代码**。

如果把开发 Java 程序比作组装一台电脑，以前需要你亲自设计电路、手动焊接口（到处手动 `new` 对象、写繁琐的底层配置）；而 Spring 就像一个**标准化的机箱与总线系统**，提供现成的接口和管家服务，你只需把业务显卡、内存插上去即可运转。

**两大核心支柱**

- **IoC / DI（控制反转 / 依赖注入）—— 对象的智能管家**
  - **以前：** `Service` 需要用到 `Dao`，必须在代码里手动 `new UserDao()`。一旦底层类修改，所有引用的地方都要跟着改（强耦合）。
  - **现在：** 对象的创建和生命周期全部交给 Spring 容器管理（控制权反转）。你需要什么组件，声明一下，Spring 就会自动把它“递”给你（依赖注入），组件之间彻底解耦。
- **AOP（面向切面编程）—— 业务的隐形外挂**
  - **以前：** 日志记录、事务回滚、权限校验等公共逻辑，必须复制粘贴到每个业务方法的前后。
  - **现在：** 把这些与核心业务无关的通用功能抽取成一个“切面”，Spring 会在方法运行时自动横向织入，核心业务代码干干净净。

**作用**

- **生态大一统：** 它提供了对数据库事务管理（Spring TX）、Web 开发（Spring MVC）、安全控制（Spring Security）的深度集成。
- **现代演进基石：** 它是微服务全家桶（Spring Cloud）与极速开发脚手架（Spring Boot）的底层基石，构成了现代 Java 后端开发的标准生态。





## 2. SpringMVC

**SpringMVC** 是 Java 生态中最主流的 Web 开发框架，属于 Spring 家族的核心组件。它的核心作用是**接收浏览器或客户端发来的网络请求，组织业务逻辑处理，并将结果（网页或 JSON 数据）返回给用户**。

如果把整个网站系统比作一家**餐厅**：

- **顾客（客户端/浏览器）**：发起点餐请求（HTTP Request）。
- **前台接待员（`DispatcherServlet`）**：负责在门口迎宾，接到点单后，根据菜单找到对应的厨师。
- **厨师长（`Controller` 控制器）**：负责统筹这道菜怎么做，调用后厨仓库（Service/Database）准备食材。
- **食材/菜品数据（`Model` 模型）**：后厨制作出来的核心数据（如用户数据、订单列表）。
- **摆盘与餐具（`View` 视图）**：把做好的菜进行精美包装（渲染成 HTML 网页或打包成 JSON 格式）呈现给顾客。

**MVC 三层职责拆解**

- **M（Model 模型）**：纯粹的数据载体，存储处理结果与业务状态。
- **V（View 视图）**：数据的视觉呈现形式，可以是服务端模板页面（如 Thymeleaf、JSP），也可以是现代前后端分离中直接返回给前端框架（Vue/React）的 JSON 数据。
- **C（Controller 控制器）**：交通枢纽，负责解析前端传来的参数、调用底层服务，并决定最终把哪些数据交给哪个视图去展示。

**核心优势**

- **低耦合高内聚**：把界面展示、流程控制与数据处理彻底分开，团队开发时前端写界面、后端写接口，互不干扰。
- **自动化参数绑定**：前端提交的表单或 JSON 数据，SpringMVC 能自动转换并填充到 Java 实体对象中，无需手动逐项解析。
- **深度融入 Spring 生态**：天然支持依赖注入（IoC）和面向切面编程（AOP），方便集成权限控制、事务管理与统一异常处理。





## 3. SpringBoot

**Spring Boot** 本质上是 Spring 框架的“开箱即用加速包”。它的诞生只有一个目的：**消灭繁琐的配置，让 Java Web 开发变得极简、快速。**

如果用通俗的生活比喻：

- **传统的 Spring / SpringMVC** 就像“买零件自己组装电脑”：你需要自己挑选主板、CPU、电源（配各种 XML 文件、配置 Tomcat 服务器、管理各种依赖版本），稍有不慎就兼容报错。
- **Spring Boot** 就像“买品牌开箱即用的一体机”：插上电源按一下开机键（直接运行 `main()` 函数），系统和常用软件全给你预装好了，立刻就能干活。

**Spring Boot 的三大杀手锏**

- **内置服务器（无需外部部署）**：以往开发 Java Web 项目必须手动安装配置 Tomcat，把项目打包成 `war` 包放进去。Spring Boot 直接把 Tomcat 嵌进项目里，打包成一个普通的 `jar` 包，敲一行命令就能直接跑。
- **起步依赖（Starter 全家桶）**：想做 Web 开发？引入一个 `spring-boot-starter-web`，它会自动把 SpringMVC、Tomcat、JSON 解析器、校验框架等全套依赖一次性下齐，且保证版本绝不冲突。
- **自动配置（约定优于配置）**：只要检测到你引入了某个依赖，它就会按照业界标准默认配置好底层参数。你只有在需要特殊定制时，才去 `application.yml` 里改一两行配置。





## 4. 关系

**Spring 是底座引擎，Spring MVC 是专攻 Web 请求的子模块，Spring Boot 是打包整合并实现“开箱即用”的敏捷脚手架。**

三者并非互相替代的关系，而是层层递进、协同工作的生态整体：

- **Spring** 是**底盘与动力系统**：提供核心组装规范（IoC 容器管理各种组件零件，AOP 提供全局切面能力）。
- **Spring MVC** 是**方向盘与中控交互**：安装在底盘上，专门负责与外界交互（接收外部 HTTP 请求、路由分发、反馈响应数据）。
- **Spring Boot** 是**出厂预装的一键启动套件**：出厂自带预设配置、内置空调与音响（内嵌 Tomcat），打成一个可执行文件，钥匙一拧（`java -jar`）直接上路。

**核心维度全景对比**

| **维度**       | **Spring Framework**                                     | **Spring MVC**                                               | **Spring Boot**                                              |
| -------------- | -------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **核心定位**   | 基础开发框架（底座引擎）                                 | 表现层 Web 框架（Spring 子模块）                             | 快速开发脚手架（全生态整合平台）                             |
| **核心职责**   | 组件解耦（IoC）、切面管理（AOP）、声明式事务管理         | HTTP 请求接收、路由分发、参数绑定、JSON/视图响应             | 依赖仲裁（Starter）、自动装配（Auto-Config）、内嵌容器、健康监控 |
| **所属层级**   | 贯穿全层（业务层 Service、持久层 DAO 等）                | 专注于 **Web 表现层**                                        | 覆盖应用**全生命周期**（搭建、配置、打包、部署、运维）       |
| **部署与运行** | 需手动构建上下文配置，常配合外部容器运行                 | 传统模式下打成 `.war` 包，依赖外部 Tomcat 部署               | 打成可执行 `.jar` 包，内置 Tomcat/Undertow，直接独立运行     |
| **典型注解**   | `@Component`、`@Service`、`@Autowired`、`@Transactional` | `@RestController`、`@RequestMapping`、`@PathVariable`、`@RequestBody` | `@SpringBootApplication`、`@EnableAutoConfiguration`、`@ConditionalOn*` |

**三者的内在联系与演进逻辑**

- **包含与继承：** Spring MVC 是 Spring 生态中的一个模块（`spring-webmvc`），它直接建立在 Spring IoC 容器之上，所有的 Controller 与拦截器天然都是 Spring 容器管理的 Bean。
- **整合与简化：** Spring Boot 并没有重写 Web 或业务引擎，它通过 `spring-boot-starter-web` 同时引入了 Spring 核心与 Spring MVC，并通过自动化配置彻底省去了传统 Spring/Spring MVC 繁重的 XML 与配置类。
- **现代落地形态：** 现代 Java 后端开发以 **Spring Boot 为工程底座**，以 **Spring 为业务与事务核心**，以 **Spring MVC 为对外暴露 RESTful API 的接口层**，三者融为一体构成了标准的企业级开发技术体系。
