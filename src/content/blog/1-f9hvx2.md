## 二、算法复杂度

### 2.1 为什么需要复杂度

评价一个算法好不好，就看两个指标：**时间**（跑多快）和**空间**（占多少内存）。

但"实际跑几秒"没法公平比较——同一份代码，在不同机器、不同语言、不同编译器下测出来的时间都不一样。所以我们需要一个**与机器无关的预估指标**：把每个基本操作当作 1 个单位时间，数一数"操作次数"随"数据规模 N"增长的趋势。这就是复杂度。

> 复杂度是**预估指标**，描述的是趋势，不是精确秒数。

### 2.2 时间复杂度

**常数操作**：执行时间固定的基本操作，如一次加减乘除、一次数组下标访问 `a[i]`、一次比较、一次赋值、位运算等。与之相对的是**非常数操作**，比如链表按下标访问（要从头走）、大整数乘法（位数越多越慢）。

**推导步骤**：

1. 把算法的每一步拆成常数操作，数出总操作次数关于 N 的表达式；
2. **只要最高阶项**，低阶项和常数项全部扔掉；
3. **最高阶项的系数也扔掉**。

**例子**：

| 操作次数表达式 | 时间复杂度 | 说明 |
|---|---|---|
| `3N² + 5N + 100` | O(N²) | 只留最高阶项，系数 3 扔掉 |
| `0.5N² + 1000N` | O(N²) | 系数再小也是 N² 阶 |
| `N + logN` | O(N) | N 比 logN 高阶 |
| `2^N + N³` | O(2^N) | 指数阶比多项式阶高 |
| `7`（与 N 无关） | O(1) | 常数阶 |

常见复杂度从小到大排序（**必须背下来**）：

```
O(1) < O(logN) < O(N) < O(N·logN) < O(N²) < O(N³) < O(2^N) < O(N!)
```

下图是增长曲线对比，可以直观感受为什么 O(N²) 和 O(N·logN) 是"天壤之别"：N = 100 万时，N² 是 10¹² 次操作（普通机器要跑几十分钟），N·logN 只有约 2×10⁷ 次（毫秒级）。

![常见时间复杂度增长曲线对比](/covers/1-f9hvx2/complexity_curves.webp)

**最坏 vs 平均**：时间复杂度一般指**最坏情况**（保证下界），但有些算法会讨论平均情况（如快速排序平均 O(N·logN)、最坏 O(N²)）。第 1 讲的三个排序里，"是否与数据状况有关"是重点，见后文。

### 2.3 空间复杂度

空间复杂度衡量算法运行过程中需要的**额外空间**（不包含输入数据本身占的空间）随 N 增长的趋势。

常见三档：

- **O(1)**：只用了有限个变量。如选择、冒泡、插入排序。
- **O(N)**：开了一个和输入同规模的辅助结构。如归并排序的辅助数组、哈希表。
- **O(N²)**：开了二维辅助结构（较少见）。

> ⚠️ **左神重点提醒：递归深度算空间复杂度！**
> 函数每递归一层，系统就要压一层栈帧。递归深度是 O(N)，空间复杂度就是 O(N)，哪怕你代码里一个数组都没开。这个坑在第 8 讲"暴力递归"会反复出现。

### 2.4 常数时间：同阶才比常数

复杂度相同（同阶）的算法，才去比常数项（实际跑的常数操作多少）。比如同样是 O(N²) 的三个排序，插入排序的常数项通常最小，实际最快。

但要注意：**阶的差距是质变，常数的差距是量变**。一个 O(N²) 算法就算常数项再小，数据一大也打不过 O(N·logN)。所以先看阶，再看常数。

## 三、三种简单排序算法

先给一个后面三个算法都要用的 `swap`。左神在第 1 讲还秀了一个"不用临时变量"的异或交换，一并记下：

```java
// 常规交换：一个临时变量
public static void swap(int[] arr, int i, int j) {
    int tmp = arr[i];
    arr[i] = arr[j];
    arr[j] = tmp;
}

// 花活：异或交换（不用临时变量）
// 原理：a ^ a = 0，a ^ 0 = a，异或满足交换律、结合律
public static void xorSwap(int[] arr, int i, int j) {
    if (i == j) {   // 坑：i == j 时（同一块内存），三次异或会把值变成 0！
        return;     // 所以必须保证 i != j
    }
    arr[i] = arr[i] ^ arr[j];
    arr[j] = arr[i] ^ arr[j];   // 此时 arr[i] = 原i ^ 原j，再异或原j = 原i
    arr[i] = arr[i] ^ arr[j];   // 再异或原i = 原j
}
```

> 异或交换面试时当谈资可以，工程里老老实实用临时变量版本——可读性更重要，而且 JVM 优化后临时变量版本并不慢。

### 3.1 选择排序（Selection Sort）

**思想**：第 0 轮在 `a[0..N-1]` 全范围找最小值，放到 `a[0]`；第 1 轮在 `a[1..N-1]` 找最小值，放到 `a[1]`……第 i 轮在 `a[i..N-1]` 找最小值放到 `a[i]`。每轮只交换一次。

![选择排序一轮示意](/covers/1-f9hvx2/selection_sort.webp)

```java
public static void selectionSort(int[] arr) {
    if (arr == null || arr.length < 2) {   // 边界防御，后面所有算法都这么写
        return;
    }
    int n = arr.length;
    // 第 i 轮：把 [i, n-1] 范围的最小值放到 i 位置
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i;                  // 先假设 i 就是最小值位置
        for (int j = i + 1; j < n; j++) {  // 遍历剩余范围
            if (arr[j] < arr[minIndex]) {
                minIndex = j;              // 只更新下标，不急着交换
            }
        }
        swap(arr, i, minIndex);            // 一轮结束才交换一次
    }
}
```

**复杂度分析**：

- 比较次数固定为 `(N-1) + (N-2) + ... + 1 = N(N-1)/2`，**与数据原始顺序无关**——给你一组已经排好序的数，选择排序照样做满 N²/2 次比较。
- 时间复杂度：**永远 O(N²)**（最好、最坏、平均都是）。
- 空间复杂度：O(1)。
- **不稳定**。反例：`[5, 8, 5, 2, 9]`，第一轮把 `a[0]` 的 5 和 2 交换，两个 5 的相对顺序就变了。

### 3.2 冒泡排序（Bubble Sort）

**思想**：从头到尾两两比较相邻元素，逆序就交换。一轮走完，最大值像气泡一样"浮"到（或者说大数"沉"到）数组末尾；然后范围缩小一位，再来一轮。

![冒泡排序一轮示意](/covers/1-f9hvx2/bubble_sort.webp)

```java
public static void bubbleSort(int[] arr) {
    if (arr == null || arr.length < 2) {
        return;
    }
    int n = arr.length;
    // 每轮把 [0, end] 范围的最大值交换到 end 位置
    for (int end = n - 1; end > 0; end--) {
        boolean swapped = false;           // 优化：整轮没交换说明已有序
        for (int i = 0; i < end; i++) {    // 相邻两两比较
            if (arr[i] > arr[i + 1]) {
                swap(arr, i, i + 1);
                swapped = true;
            }
        }
        if (!swapped) {
            break;                         // 提前结束
        }
    }
}
```

**复杂度分析**：

- 最坏 / 平均：O(N²)。
- 最好（加了 `swapped` 优化后，输入已有序）：**O(N)**，一轮扫描发现没交换直接退出。
- 空间复杂度：O(1)。
- **稳定**：相等元素不会交换（条件是 `>` 而不是 `>=`），相对顺序不变。

### 3.3 插入排序（Insertion Sort）

**思想**：类比**摸扑克牌整理手牌**——每次新摸一张牌，从右往左和手里的牌比较，插到第一个不比它大的牌后面。对应到数组：保证 `a[0..i]` 有序，把新来的 `a[i]` 插入到前面有序区的正确位置。

![插入排序：整理扑克牌](/covers/1-f9hvx2/insertion_sort.webp)

```java
public static void insertionSort(int[] arr) {
    if (arr == null || arr.length < 2) {
        return;
    }
    int n = arr.length;
    // 保证 [0, i] 有序：把新来的 arr[i] 插入前面有序区
    for (int i = 1; i < n; i++) {
        // j 从 i 开始：只要前一个比当前大，就交换往前挪
        for (int j = i; j > 0 && arr[j] < arr[j - 1]; j--) {
            swap(arr, j, j - 1);
        }
    }
}
```

更高效的"先移位、后插入"写法（减少交换次数，每次只搬动一次）：

```java
public static void insertionSort2(int[] arr) {
    if (arr == null || arr.length < 2) {
        return;
    }
    int n = arr.length;
    for (int i = 1; i < n; i++) {
        int key = arr[i];              // 新摸的牌先拿在手上
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];       // 比 key 大的牌统一后移一位
            j--;
        }
        arr[j + 1] = key;              // 腾出的空位插入 key
    }
}
```

**复杂度分析（本课重点！）**：

- 插入排序的运行时间**与数据状况有关**：
  - 最好（已有序）：内层循环一次都不进，**O(N)**；
  - 最坏（逆序）：每次都要插到最前面，O(N²)。
- 空间复杂度：O(1)。
- **稳定**：只在"前一个**严格大于**当前"时才移动，相等元素不交换。

> 左神在这里点出一个重要观念：**不要听到 O(N²) 就嫌弃插入排序**。
> 它最好情况 O(N)、常数项小、稳定，工程上很多高级排序（如快速排序、TimSort）在小规模数据段都会切换成插入排序收尾。面试时能说出"插入排序与数据状况有关"是加分项。

### 3.4 三种排序对比

![三种简单排序对比](/covers/1-f9hvx2/sort_compare.webp)

| 排序 | 最好 | 最坏 / 平均 | 空间 | 稳定性 | 与数据状况有关？ | 核心思想 |
|---|---|---|---|---|---|---|
| 选择排序 | O(N²) | O(N²) | O(1) | 不稳定 | 无关 | 每轮选最小放前面 |
| 冒泡排序 | O(N) | O(N²) | O(1) | 稳定 | 有关 | 相邻比较，大数沉底 |
| 插入排序 | O(N) | O(N²) | O(1) | 稳定 | 有关 | 像摸牌，逐个插入有序区 |

**稳定性**的定义：排序后，相等值的元素保持原来的相对先后顺序。面试常问"哪些排序稳定"，第 1 讲先记住：冒泡、插入稳定，选择不稳定；后面的归并稳定、快排不稳定、桶排序不稳定、基数/计数稳定。

## 四、对数器：自己验证算法对不对

### 4.1 什么是对数器

写完一个算法，怎么知道它对不对？左神的答案：**不要等别人给测试数据，自己造**。

对数器由四部分组成：

1. **方法 A**：你想测试的方法（比如你刚写的选择排序）；
2. **方法 B**：一个绝对正确但可能很慢的方法（比如系统自带的 `Arrays.sort`，或者暴力解）；
3. **随机数据生成器**：随机产生大量样本，A 和 B **跑同一份样本**；
4. **对比器**：逐位比较两个结果，一旦不同就打印出错样本，方便复现修 bug。

跑上几十万组随机数据都一致，你的算法基本就可以信了。以后每次改算法，跑一遍对数器立刻知道改对没有。

![对数器流程](/covers/1-f9hvx2/comparator_flow.webp)

### 4.2 完整代码（可直接运行）

```java
import java.util.Arrays;

public class SortComparator {

    // ===== 方法A：你想测试的算法（这里用选择排序演示） =====
    public static void selectionSort(int[] arr) {
        if (arr == null || arr.length < 2) {
            return;
        }
        int n = arr.length;
        for (int i = 0; i < n - 1; i++) {
            int minIndex = i;
            for (int j = i + 1; j < n; j++) {
                if (arr[j] < arr[minIndex]) {
                    minIndex = j;
                }
            }
            swap(arr, i, minIndex);
        }
    }

    // ===== 方法B：绝对正确的对照方法 =====
    public static void comparator(int[] arr) {
        Arrays.sort(arr);   // 系统排序，可信
    }

    // ===== 随机数组生成器：长度 [0, maxLen]，值 [-maxValue, maxValue] =====
    public static int[] randomArray(int maxLen, int maxValue) {
        int len = (int) (Math.random() * (maxLen + 1));  // Math.random() ∈ [0,1)
        int[] arr = new int[len];
        for (int i = 0; i < len; i++) {
            arr[i] = (int) (Math.random() * (maxValue * 2 + 1)) - maxValue;
        }
        return arr;
    }

    // 拷贝一份，保证两个方法跑的是同一份数据
    public static int[] copyArray(int[] arr) {
        int[] res = new int[arr.length];
        for (int i = 0; i < arr.length; i++) {
            res[i] = arr[i];
        }
        return res;
    }

    public static void swap(int[] arr, int i, int j) {
        int tmp = arr[i];
        arr[i] = arr[j];
        arr[j] = tmp;
    }

    public static void main(String[] args) {
        int testTimes  = 500000;  // 测试轮数：越大越可信
        int maxLen     = 100;     // 数组最大长度
        int maxValue   = 100;     // 元素绝对值上限（值域小才能撞出重复值，测稳定性相关 bug）
        for (int i = 0; i < testTimes; i++) {
            int[] arr1 = randomArray(maxLen, maxValue);
            int[] arr2 = copyArray(arr1);
            selectionSort(arr1);  // 方法A
            comparator(arr2);     // 方法B
            if (!Arrays.equals(arr1, arr2)) {
                System.out.println("出错了！以下样本两种方法结果不一致：");
                System.out.println(Arrays.toString(arr1));
                break;
            }
        }
        System.out.println("对数器测试结束，全部通过！");
    }
}
```

### 4.3 对数器的使用心法

- **值域不要开太大**：`maxValue` 和 `maxLen` 差不多大甚至更小，才能频繁产生重复值，暴露边界 bug。
- **出错样本要打印**：随机数据最大的好处是出错时能拿到一个可复现的小样本，对着它 debug 比盯着代码空想快十倍。
- **贯穿全课程**：后面每一讲左神写完新算法都会挂上对数器跑一遍，这个工具要从第 1 讲就用熟。

## 五、二分法详解

二分法是第 1 讲的第二个重头。左神用它传达一个观念：**二分的本质不是"数组有序"，而是"每一轮都能根据某个性质砍掉一半的搜索范围"**。下面三道题层层递进。

### 5.1 题一：有序数组中找某个数

最经典的二分：数组有序，找 `target`，返回下标，找不到返回 -1。

![二分查找](/covers/1-f9hvx2/binary_search.webp)

```java
// 有序数组中找 target，返回下标；找不到返回 -1
public static int binarySearch(int[] arr, int target) {
    if (arr == null || arr.length == 0) {
        return -1;
    }
    int L = 0, R = arr.length - 1;
    while (L <= R) {                          // L == R 时范围里还有一个数，不能漏
        int mid = L + ((R - L) >> 1);         // 等价 (L+R)/2，但防溢出；>>1 即除2
        if (arr[mid] == target) {
            return mid;                       // 命中
        } else if (arr[mid] < target) {
            L = mid + 1;                      // mid 及其左边全排除
        } else {
            R = mid - 1;                      // mid 及其右边全排除
        }
    }
    return -1;
}
```

**为什么是 O(logN)**：每轮搜索范围减半，N → N/2 → N/4 → … → 1，砍的次数就是 log₂N。10 亿个数据也只要约 30 次比较。

两个写法细节（左神风格）：

- `mid = L + ((R - L) >> 1)`：避免 `(L + R)` 在超大下标时整型溢出；位运算也比除法快一点。
- 循环条件 `L <= R` 配合 `L = mid + 1 / R = mid - 1`：保证每轮范围严格缩小，不会死循环，也不会漏掉 `L == R` 的最后一个候选。

### 5.2 题二：有序数组中找 >= x 的最左位置

进阶版：不找相等，找**满足某个条件的最左（或最右）位置**。技巧是多用一个变量 `ans` 记录"目前为止满足条件的最左位置"，命中后不退出，继续往左收缩。

```java
// 有序数组中，返回 >= x 的最左位置；不存在返回 -1
public static int mostLeftNoLess(int[] arr, int x) {
    int L = 0, R = arr.length - 1;
    int ans = -1;                 // 记录答案：目前满足 arr[mid] >= x 的最左下标
    while (L <= R) {
        int mid = L + ((R - L) >> 1);
        if (arr[mid] >= x) {
            ans = mid;            // mid 满足条件，先记下来
            R = mid - 1;          // 但左边可能还有更靠左的，继续往左找
        } else {
            L = mid + 1;          // mid 太小，答案只可能在右边
        }
    }
    return ans;
}
```

同理可以写 `> x 的最左`、`<= x 的最右`、`< x 的最右`，四兄弟一起练，面试变体逃不出这四种。

### 5.3 题三：局部最小值问题（无序数组也能二分！）

**题目**：定义"局部最小"——

- `a[0] < a[1]` 时，`a[0]` 是局部最小；
- `a[N-1] < a[N-2]` 时，`a[N-1]` 是局部最小；
- `a[i-1] > a[i] < a[i+1]` 时，`a[i]` 是局部最小。

给定一个**任意相邻两数都不相等**的数组（注意：**无序**），返回任意一个局部最小的下标。要求比 O(N) 扫一遍更快。

![局部最小值](/covers/1-f9hvx2/local_min.webp)

**为什么无序也能二分**：看"趋势"。先查边界：

- 若 `a[0] < a[1]`，直接返回 0；若 `a[N-1] < a[N-2]`，直接返回 N-1；
- 否则此时 `a[0] > a[1]`（左边界呈下降趋势）、`a[N-2] < a[N-1]`（右边界呈上升趋势）。想象一条先往下走、最后又往上走的折线，中间**必然**存在一个谷底（局部最小）。

于是看 `mid`：

- 若 `a[mid]` 比两边都小 → 它就是局部最小，返回；
- 若 `a[mid] > a[mid-1]` → 左边是"下降进入 mid"的趋势，而左边界也是下降趋势，`[L, mid-1]` 这段里必然有谷底，往**左**半砍；
- 若 `a[mid] > a[mid+1]` → 同理往**右**半砍。

每一轮范围减半 → **O(logN)**。

```java
// 相邻不相等的数组中，返回任意一个局部最小的下标
public static int localMin(int[] arr) {
    if (arr == null || arr.length == 0) {
        return -1;
    }
    int n = arr.length;
    if (n == 1 || arr[0] < arr[1]) {     // 左边界直接是局部最小
        return 0;
    }
    if (arr[n - 1] < arr[n - 2]) {       // 右边界直接是局部最小
        return n - 1;
    }
    // 走到这里说明：a[0] > a[1]（左边下降），a[n-2] < a[n-1]（右边上升）
    int L = 1, R = n - 2;
    while (L < R) {                      // L == R 时，由两侧趋势保证它就是局部最小
        int mid = L + ((R - L) >> 1);
        if (arr[mid] > arr[mid - 1]) {
            R = mid - 1;                 // 左侧有下降趋势，谷底在左半
        } else if (arr[mid] > arr[mid + 1]) {
            L = mid + 1;                 // 右侧有下降趋势，谷底在右半
        } else {
            return mid;                  // 比两边都小，就是局部最小
        }
    }
    return L;                            // L == R，收敛点即答案
}
```

**这道题的收获（左神原话精神）**：二分的前提从来不是"有序"，而是**能否利用某种信息每轮砍掉一半**。有序数组用的是"大小关系"，局部最小值用的是"边界趋势"。建立这个认知后，后面课程里的"二分答案""在旋转数组上二分"才不会懵。

## 六、本课核心思想总结

1. **复杂度是尺子**：先报复杂度再讲思路；只看最高阶项；递归深度计入空间复杂度。
2. **阶是质变，常数是量变**：O(N²) 到 O(N·logN) 是算法层面的胜利；同阶才比常数。下一讲的归并排序、快速排序就是来消灭 N² 的。
3. **简单排序各有性格**：选择"与数据无关、永远 N²、不稳定"；冒泡和插入"与数据有关、最好 O(N)、稳定"；插入排序常数小，工程上给高级排序收尾。
4. **对数器是方法论**：随机样本 + 暴力对照 + 大样本量，自己掌握算法正确性，不靠人肉测试数据。
5. **二分的本质是"每轮砍一半"**：有序找数、找最左满足条件、无序找局部最小，三个例子一个比一个深刻地说明这一点。

## 七、易错点与面试考点速记

| 考点 | 结论 / 提醒 |
|---|---|
| 选择排序稳定性 | 不稳定（`[5,8,5,2,9]` 反例） |
| 冒泡 / 插入稳定性 | 稳定（比较条件用严格大于/小于） |
| 插入排序最好复杂度 | O(N)（已有序），与数据状况有关 |
| 选择排序最好复杂度 | 仍 O(N²)，与数据状况无关 |
| 递归的空间复杂度 | 递归深度算空间！ |
| 二分 mid 写法 | `L + ((R - L) >> 1)` 防溢出 |
| 二分循环条件 | `while (L <= R)` 配 `mid±1`，不漏不循环 |
| 找"最左满足条件" | 命中后记录 `ans` 并继续向左收缩，不直接 return |
| 局部最小值 | 无序数组也能二分，靠边界趋势信息砍半，O(logN) |
| 异或交换 | `i == j` 时会把值清零，必须判等 |
| 对数器 | 值域开小一点以产生重复值；出错打印样本 |
