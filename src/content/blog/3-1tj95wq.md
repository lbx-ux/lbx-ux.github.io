## 二、基于比较的排序下界：O(N log N) 是天花板

### 2.1 什么叫"基于比较的排序"

算法内部**只允许做一件事**：拿两个元素比大小（再根据结果交换/移动）。选择、冒泡、插入、归并、快排、堆排全都在这个圈里——它们不关心元素是年龄还是成绩，只关心比较结果。

### 2.2 决策树论证

把算法的执行过程画成一棵二叉树：每个内部节点是一次比较（"a < b？"），两条分支是两种答案，每条从根到叶的路径就是算法在某种输入下的完整执行过程，叶子是算法最终给出的排列。

关键两步：

1. **叶子数 ≥ N!**。算法必须能产出输入的每一种可能排列（输入可能是任意顺序），不同排列必须走到不同叶子，而 N 个数的排列共 N! 种，所以叶子至少 N! 个。
2. **高度为 h 的二叉树最多 2^h 个叶子**。于是 `2^h ≥ N!`，即 `h ≥ log2(N!)`。

由斯特林公式 `log2(N!) ≈ N log2 N − 1.44N`，量级就是 **Ω(N log N)**。树高是最坏情况下的比较次数，所以：

> **任何基于比较的排序，最坏时间复杂度不可能低于 O(N log N)。** 归并、堆排踩到了这条线，所以它们是"渐近最优"的比较排序。

![决策树与下界](/covers/3-1tj95wq/decision_tree.webp)

上图是 3 个数的决策树示意：3! = 6 种排列对应至少 6 个叶子，树高至少 ⌈log2 6⌉ = 3，即最坏至少比 3 次。N 变大时这个论证原样成立，只是数字换成 N!。

### 2.3 下界的"逃生门"

注意下界的前提是"**只比较**"。如果算法偷看数据本身的信息——比如知道元素是整数、知道值域范围、知道位数——就可以不比较直接定位，桶系排序就是这条路。这也是为什么计数排序 O(N) 并不"违反"下界：它根本不是比较排序。

## 三、桶系排序的总思想：不比较，直接"对号入座"

桶系三兄弟（桶排序、计数排序、基数排序）共享一个套路：

1. 按数据的某个特征（值域区间 / 值本身 / 某一位的数字）把元素**散进有限个桶**；
2. 桶内或桶间按规则整理；
3. 按桶的顺序把元素收回来，即有序。

复杂度不再来自"比较次数"，而来自"数据特征的规模"（值域 K、位数 len），所以能到 O(N)。代价是**不通用**：数据不是整数、值域爆炸、分布极端不均时，桶系就废了或退化了。

**桶排序（按值域分桶）** 是概念原型：把 [min, max] 均分成 k 个区间桶，元素按值落桶，桶内用插入排序，再按桶序拼接。数据均匀分布时平均 O(N)；数据全挤进一个桶时退化成桶内插入排序 O(N²)。左神课上点到为止，重点是下面两个。

## 四、计数排序：从朴素版到稳定版

### 4.1 朴素版：计数后回填

适用：**非负整数**（负数见 4.3 的偏移技巧）。思路直白：开一个 `count[v]` 记录值 v 出现几次，然后从 0 到 max 把每个值按次数写回原数组。

```java
// 朴素计数排序：只适用于非负整数，不稳定
public static void countingSortNaive(int[] arr) {
    if (arr == null || arr.length < 2) {
        return;
    }
    int max = arr[0];
    for (int x : arr) {              // 先找最大值，决定 count 数组开多大
        max = Math.max(max, x);
    }
    int[] count = new int[max + 1];  // 空间 O(K)，K = 最大值+1
    for (int x : arr) {
        count[x]++;                  // 值当下标，直接计数
    }
    int i = 0;
    for (int v = 0; v <= max; v++) { // 按值从小到大回填
        while (count[v]-- > 0) {
            arr[i++] = v;
        }
    }
}
```

- 时间 **O(N + K)**，K 为值域大小；空间 **O(K)**。
- **不稳定**：回填时只认值不认人，相等元素的原始先后顺序没了。对纯整数无所谓，但如果排的是"按成绩排学生对象"，不稳定就乱套了。

### 4.2 稳定版：前缀和 + 倒序输出

稳定版是面试和基数排序真正要用的版本。核心改造两步：

1. **前缀和**：把 `count[v]` 从"v 出现几次"加工成"**≤ v 的元素共几个**"（即 v 这类元素在结果里的"末位 + 1"）。
2. **倒序扫原数组**：从后往前取元素 v，它该放的位置是 `--count[v]`。倒序保证了：相等的值，原数组里靠后的那个后处理、放到更靠后的位置 → **稳定**。

![稳定计数排序四步走](/covers/3-1tj95wq/counting_stable.webp)

```java
// 稳定计数排序（配合偏移量支持任意整数）
public static void countingSort(int[] arr) {
    if (arr == null || arr.length < 2) {
        return;
    }
    int min = arr[0], max = arr[0];
    for (int x : arr) {              // 找值域 [min, max]
        min = Math.min(min, x);
        max = Math.max(max, x);
    }
    int[] count = new int[max - min + 1];       // 偏移：值 v 落在下标 v-min
    for (int x : arr) {
        count[x - min]++;
    }
    for (int i = 1; i < count.length; i++) {    // 前缀和：count[i] = ≤(i+min) 的个数
        count[i] += count[i - 1];
    }
    int[] help = new int[arr.length];
    for (int i = arr.length - 1; i >= 0; i--) { // 倒序输出 → 稳定
        help[--count[arr[i] - min]] = arr[i];
    }
    for (int i = 0; i < arr.length; i++) {      // 拷回
        arr[i] = help[i];
    }
}
```

复杂度：时间 **O(N + K)**，空间 **O(N + K)**（help + count），**稳定**。

> 左神强调"倒序"不是玄学：前缀和之后 `count[v]` 指向的是 v 这类元素**最后一个**该去的位置，从后往前放，正好让"后出现的占后面"，相等元素的相对顺序就保住了。正序放则相反，会破坏稳定性。

### 4.3 偏移技巧（负数怎么办）

计数排序的下标必须是自然数。遇到负数：整体减去 min，把值域平移到从 0 开始（上面代码已内置）。这个"先平移再处理"的技巧在哈希、大数据题里也常用。

## 五、基数排序：按位做稳定计数排序

### 5.1 思想：低位先排，高位后拍板

十进制整数，从**个位**开始，依次对"当前位"做一轮**稳定**计数排序，直到最大值的最高位。全部轮次结束后整体有序。这叫 LSD（Least Significant Digit first）。

为什么内层必须稳定？看两位数的例子：先按个位排完，再按十位排。当两个数十位相同（比如 3**1** 和 3**7**）时，十位这一轮是"平局"，最终顺序必须沿用个位那一轮的结果（1 在前 7 在后）——只有稳定排序才能在"平局"时不破坏已有顺序。**高位后处理 + 内层稳定 = 低位的功劳不被抹掉**。

![基数排序 LSD 三轮示例](/covers/3-1tj95wq/radix_lsd.webp)

### 5.2 完整代码

```java
// 基数排序（LSD）：只适用于非负整数
public static void radixSort(int[] arr) {
    if (arr == null || arr.length < 2) {
        return;
    }
    int max = arr[0];
    for (int x : arr) {                       // 找最大值
        max = Math.max(max, x);
    }
    int len = String.valueOf(max).length();   // 最大值的位数 = 轮数

    int[] help = new int[arr.length];         // 每轮输出的暂存区
    int[] count = new int[10];                // 十进制的 10 个桶（0~9）
    for (int d = 0; d < len; d++) {           // 从个位开始，一轮一位
        int divisor = (int) Math.pow(10, d);  // 当前位的权：1, 10, 100...
        // 1) 计数：当前位是几就 count[几]++
        for (int x : arr) {
            count[(x / divisor) % 10]++;
        }
        // 2) 前缀和：count[i] = 当前位 ≤ i 的个数
        for (int i = 1; i < 10; i++) {
            count[i] += count[i - 1];
        }
        // 3) 倒序输出到 help → 这一轮是稳定排序
        for (int i = arr.length - 1; i >= 0; i--) {
            help[--count[(arr[i] / divisor) % 10]] = arr[i];
        }
        // 4) 拷回，进入下一位
        for (int i = 0; i < arr.length; i++) {
            arr[i] = help[i];
        }
        java.util.Arrays.fill(count, 0);      // 清空计数，下一轮复用
    }
}
```

### 5.3 复杂度与适用

- 时间 **O(N · len)**：len 轮，每轮 O(N + 10)。注意它和"比较"无关，N 再大也只是轮数（位数）不变。
- 空间 **O(N)**：help 数组；count 固定 10 个是常数。
- **稳定**（每轮都稳定，稳定性层层传递）。
- 局限：只伺候非负整数（负数用偏移）、进制可换（十进制 10 桶、二进制 2 桶、甚至 256 桶按字节拆——工程上高速排序常这么干）。

> 左神延伸：基数排序的"按位稳定排序"套路可以推广到**字符串按字典序排序**（把字符当"位"，从末字符往前做稳定计数排序），面试偶尔会考这个变体。

## 六、排序大总结与工程问题

### 6.1 全家福对比表

![排序算法全家福](/covers/3-1tj95wq/sort_final.webp)

| 排序 | 时间 | 空间 | 稳定性 | 一句话特点 |
|---|---|---|---|---|
| 选择 | O(N²) | O(1) | 不稳定 | 与数据状况无关 |
| 冒泡 | O(N²)（最好 O(N)） | O(1) | 稳定 | 相邻交换，常数大 |
| 插入 | O(N²)（最好 O(N)） | O(1) | 稳定 | 常数极小，近乎有序时飞快 |
| 归并 | O(N log N) | O(N) | **稳定** | 比较排序里唯一稳定（本课范围） |
| 快排 3.0 | O(N log N) 期望 | O(log N) | 不稳定 | 常数项最小，工程默认 |
| 堆排 | O(N log N) | O(1) | 不稳定 | 空间最优 |
| 计数 | O(N + K) | O(N + K) | 稳定 | 值域 K 不能太大 |
| 基数 | O(N · len) | O(N) | 稳定 | 整数按位，len 为位数 |

把三讲合起来看，左神给出的选型逻辑是**三个维度做取舍**：时间复杂度、空间复杂度、稳定性，外加一个隐藏维度"常数项"。经典结论再背一遍：**时间 O(N log N) + 空间 O(1) + 稳定，三者不可兼得**（工程意义上）。

### 6.2 工程问题：`Arrays.sort` 到底用了谁？

左神课上和面试都爱问"JDK 的排序实现"，结论（以 JDK 8+ 为准）：

1. **基本类型数组**（如 `int[]`）：不需要稳定（两个 5 交换了没人看得出来），用**双轴快排（Dual-Pivot Quicksort）**；数组很小（≤47）时直接退化成**插入排序**——常数项小。
2. **对象数组**（如 `Integer[]`）：要求稳定（比较器语义下相等对象不能乱序），用 **TimSort**——归并排序的魔改，能利用数组中已有的有序段（run），近乎有序时接近 O(N)。
3. 为什么不用堆排？常数项比快排大，缓存局部性也差；为什么不用归并排基本类型？要 O(N) 额外空间且没必要稳定。

> 左神方法论：面试被问"最好的排序是什么"，标准答案是"**没有最好，只有最合适**"——先看数据特性（整数？值域？近乎有序？），再看约束（要不要稳定、给不给额外空间），最后按常数项选实现。这套"按需求取舍"的话术本身就是考点。

### 6.3 桶系 vs 比较系的边界

- 数据是整数且值域/位数可控 → 计数/基数，O(N) 吊打一切。
- 数据通用（对象、浮点、比较器）→ 只能在比较系里选，N log N 是天花板。
- 这正好呼应 2.2 的下界：桶系之所以快，是因为它**不在比较排序的集合里**，下界管不着它。

## 七、易错点与面试考点速记

| 考点 | 结论 / 提醒 |
|---|---|
| 比较排序下界 | 决策树 N! 叶子 → 最坏 Ω(N log N)；前提"只比较" |
| 桶系为何能 O(N) | 利用数据信息绕过比较，不在下界约束内 |
| 计数排序朴素版 | 计数后回填，不稳定，空间 O(K) |
| 计数排序稳定版 | 前缀和 + **倒序**输出；相等时后出现的占后位 |
| 负数处理 | 整体减 min 平移到非负（偏移技巧） |
| 基数排序内层 | 必须**稳定**，否则低位的排序成果被高位轮抹掉 |
| 基数排序方向 | LSD 从低位到高位；轮数 = 最大值位数 |
| 基数复杂度 | O(N·len)，与比较次数无关 |
| Arrays.sort(int[]) | 双轴快排，小数组插入排序 |
| Arrays.sort(对象) | TimSort（归并系，稳定） |
| 三者不可兼得 | 时间 N log N + 空间 O(1) + 稳定 |
| 选型话术 | 没有最好只有最合适：数据特性 → 约束 → 常数项 |
